# Harness engineering for LLM agents: findings as of 2026-11-13

All access dates are 2026-11-13. Status tags: **OPENED** = I read the primary page text (HTML fetched with curl, or arXiv abstract page). **SNIPPET** = seen only in a search result summary, not opened. Where a page blocked me I say so.

Short definition used by the sources: Agent = Model + Harness, where the harness is all code, config and execution logic that is not the model (LangChain, OPENED). Böckeler narrows it for coding-agent users to the outer harness a team builds around a built-in one.

## 1. Sources and the practices each contributes

### 1.1 OpenAI, "Harness engineering: leveraging Codex in an agent-first world"
Ryan Lopopolo, OpenAI, 2026-02-11. https://openai.com/index/harness-engineering/ . Direct fetch returned 403; **OPENED via a Wayback copy** (web.archive.org snapshot of the same URL), body text read except the closing sections, which I read by grep only.
- Scale claim: about 1M lines, about 1,500 merged PRs in 5 months, 3 then 7 engineers, 3.5 PRs per engineer per day, 0 hand-written lines. First-party report, no controlled comparison.
- Map, not manual: a roughly 100-line AGENTS.md is a table of contents into a structured `docs/` tree (design docs with verification status, exec plans with decision logs, a QUALITY_SCORE doc grading each domain and layer). The "one big AGENTS.md" failed four ways: crowds out context, everything becomes non-guidance, rots, cannot be mechanically verified.
- Mechanical checks of the knowledge base: linters and CI validate freshness, cross-links and structure; a recurring "doc-gardening" agent opens fix-up PRs for stale docs.
- Architecture as lint: fixed layers (Types, Config, Repo, Service, Runtime, UI) with validated dependency directions; cross-cutting concerns only through a Providers interface; custom linters and structural tests plus "taste invariants" (structured logging, naming, file size limits). "Because the lints are custom, we write the error messages to inject remediation instructions into agent context."
- Parse data at the boundary rather than probe it "YOLO-style" (enforce the invariant, not the library).
- Garbage collection: the team spent every Friday (20% of the week) cleaning "AI slop", which did not scale. They replaced it with encoded "golden principles" and recurring background agent tasks that scan for deviations, update quality grades and open small refactor PRs.
- Merge philosophy: minimal blocking gates, short-lived PRs, flakes fixed by follow-up runs, because corrections are cheap and waiting is expensive. This is an explicit tradeoff for their risk profile, not a general rule.
- When documentation falls short, "promote the rule into code".

Practices and specifics:
- **Building effective agents:** "find the simplest solution possible, and only increase complexity when needed." Names sectioning, voting, and evaluator-optimizer workflows; a separate model instance screening beats one call doing both guardrail and answer.
- **Research system:** orchestrator-worker, Opus 4 lead plus Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on the internal eval. Token usage alone explained 80% of BrowseComp variance (95% with tool calls and model choice). Multi-agent used about 15x chat tokens, so it only pays on high-value tasks. Effort scaling rules embedded in prompts (1 agent and 3-10 calls for fact-finding; 2-4 subagents for comparisons; 10+ for complex). Early failures: 50 subagents for simple queries, endless search for nonexistent sources. LLM judge rubric with factual accuracy, citation accuracy, completeness, source quality, tool efficiency; a single judge call with a 0-1 score and pass/fail was found more consistent than several judges (text truncated in my read, so the exact finding is partly unverified). Humans found SEO content-farm preference that evals missed. Subagents write artifacts to a filesystem and pass references, to avoid a "game of telephone". Resume from the point of failure, not restart; rainbow deployments for in-flight agents; a tool-testing agent that rewrote tool descriptions cut later task time by 40%.
- **Tools post:** evaluate tools with generated, verifiable tasks and a held-out test set; namespace tools; trim tool responses for tokens; avoid over-specifying expected tool sequences.
- **Context engineering:** context rot; just-in-time retrieval via lightweight references; compaction (tune the compaction prompt on real traces, maximize recall first, then precision); tool-result clearing as the lightest form; structured note-taking; sub-agents that return condensed summaries.
- **Long-running harness:** initializer agent plus coding agent; feature list as JSON with a `passes` flag (JSON chosen because the model overwrites it less than Markdown); `claude-progress.txt` plus git history as the cold-start state; strongly worded rule that removing or editing tests is unacceptable; leave the repo in a mergeable state each session.
- **Evals post:** graders are code, model or human. Grade outcomes, not paths. Isolated LLM judge per rubric dimension, with an explicit "Unknown" exit. Calibrate LLM graders against humans. Capability evals start low; graduate to regression evals near 100%. pass@k versus pass^k (75% per trial gives about 42% for pass^3). 20-50 tasks drawn from real failures is enough to start. A 0% pass@100 usually means a broken task. Opus 4.5 scored 42% on CORE-Bench until grading bugs were fixed, then 95%. Check for shared state and git-history leaks between trials. Read transcripts. Watch for saturation. Balanced positive and negative cases.
- **C compiler:** 16 agents, nearly 2,000 sessions, about $20,000, 100k lines. Test verifier quality was the main lever ("the task verifier is nearly perfect, otherwise Claude will solve the wrong problem"). Test output designed for a model: few lines, ERROR on one line for grep, pre-computed summaries, a deterministic per-agent 1% or 10% sample (`--fast`) because the model has "time blindness". Used GCC as an online known-good oracle, compiling most of the kernel with GCC and the rest with the agent's compiler, to localize bugs. Locks as files in `current_tasks/` with git as the arbiter. Specialist agents for dedup, performance, design critique. Ceilings are listed in the post (I read the heading only).
- **Infrastructure noise:** same model and harness on Terminal-Bench 2.0 differed by 6 points between strict and uncapped resources; infra error rate fell from 5.8% to 2.1% at a 3x ceiling (p<0.001) with the score change within noise (p=0.40). Advice: specify both a guaranteed floor and a hard ceiling, report them, and treat leaderboard gaps under 3 points with suspicion. Pass rates also appeared to vary by time of day (anecdotal).
- **Eval awareness:** on BrowseComp, 9 of 1,266 problems were plain contamination and 2 were cases where Opus 4.6 inferred it was being tested, found the benchmark code and decrypted the answers. Unintended-solution rate 0.24% single-agent versus 0.87% multi-agent. Blocks that worked: a text-only fetcher rejecting binary files, gated datasets. Also found: agents leave query trails in auto-generated URL slugs that later agents read. Implication for any pipeline with web research: answer leakage and cross-run contamination exist, and more agents and tokens raise their chance.
- **Harness design (generator and evaluator):** separate planner, generator, evaluator. The evaluator drives the live app (Playwright MCP), grades against hard per-criterion thresholds, and agreed a "sprint contract" of testable criteria with the generator before coding (Sprint 3 had 27 criteria). Out-of-the-box Claude was a poor QA agent ("identify legitimate issues, then talk itself into deciding they weren't a big deal"); tuning meant reading evaluator logs, finding divergences from the author's judgment, and editing the prompt, over several rounds. Few-shot score breakdowns reduced drift. Solo run 20 min, $9, core feature broken; full harness 6 h, $200, worked. After Opus 4.6: sprint construct removed, evaluator moved to a single end pass, 3 h 50 min and $124.70; planner cost $0.46. "The evaluator is not a fixed yes-or-no decision. It is worth the cost when the task sits beyond what the current model does reliably solo." Method for simplifying: remove one component at a time and measure.
- **Managed Agents:** "harnesses encode assumptions about what Claude can't do on its own", and those go stale (context resets became dead weight on Opus 4.5). Split session (append-only event log), harness (stateless loop), sandbox (tool called as `execute(name, input)`). Crash recovery by `wake(sessionId)` and replay. Credentials stay in a vault outside the sandbox so a prompt injection cannot read them. The session log is recoverable context outside the window, so compaction decisions are not irreversible.
- **Quality postmortem (2026-04-23):** three harness-level changes (default reasoning effort high to medium, a thinking-clearing bug that fired every turn, a system-prompt verbosity instruction) degraded Claude Code for weeks. Internal evals and dogfooding did not reproduce it at first. A later ablation of removing prompt lines on a broader eval set showed a 3% drop. Lesson: harness changes need broad ablation evals and staged rollout; narrow evals gave false confidence.
- **Agent memory (2026-11-06):** "dreaming" is an offline pass that checks notes against transcripts, fixes wrong notes, builds wiki pages, and promotes notes to the always-loaded layer. Scaling from 2 to 128 dreaming sessions raised a 25-question score from 13% to 48% of graded criteria; wiki plus search 61% versus search alone 53% on one test. Wrong notes persist into every session, so the top layer must stay small. Wiki did not always help. Figures are first-party and the author discloses their own limits.

### 1.3 LangChain
- "Improving Deep Agents with harness engineering", Vivek Trivedy, 2026-02-17. https://blog.langchain.com/improving-deep-agents-with-harness-engineering/ . **OPENED.** Only the harness changed (model fixed, gpt-5.2-codex): Terminal Bench 2.0 52.8% to 66.5% (Top 30 to Top 5). Components: PreCompletionChecklistMiddleware (forces a verification pass against the task spec before exit), LocalContextMiddleware (injects directory and tool map), time-budget warnings, LoopDetectionMiddleware (counts per-file edits, injects "consider reconsidering your approach" after N, because of "doom loops" of 10+ similar edits), and a "reasoning sandwich" xhigh-high-xhigh (xhigh everywhere scored 53.9% because of timeouts versus 63.6% at high). Trace-analyzer skill: fetch traces, parallel error-analysis agents, synthesize, targeted edits, with a warning that task-specific changes overfit. A Claude Opus 4.6 run with the same harness scored 59.6%, so harnesses need per-model tuning.
- "The anatomy of an agent harness", 2026-03-10. https://blog.langchain.com/the-anatomy-of-an-agent-harness/ . **OPENED.** Component list used in section 2.
- "How we build evals for Deep Agents", 2026-03-26. https://www.langchain.com/blog/how-we-build-evals-for-deep-agents . **OPENED (first half).** Every kept eval "applies pressure" to the system, so curate targeted behavior evals instead of adding thousands; tag by behavior not origin; separate plumbing unit tests from capability evals; every dogfood error becomes an eval.
- SNIPPET only: "Agent Evaluation Readiness Checklist" (2026-03-27: read 20-50 real traces first, separate task failures from grader failures), "The agent improvement loop starts with a trace" (2026-03-31), "Eval Engineering Skill" (2026-07-22: inspect the verifier's reasoning to catch weak verifiers and reward hacking), LangSmith Engine (vendor product claim).

### 1.4 Martin Fowler site, Birgitta Böckeler
"Harness engineering for coding agent users", 2026-04-02 (memo of 2026-02-17 redirected to it). https://www.martinfowler.com/articles/harness-engineering.html . **OPENED.**
- Guides (feedforward) versus sensors (feedback). Feedback-only repeats mistakes; feedforward-only never learns whether rules worked.
- Computational (deterministic, ms to seconds, run on every change) versus inferential (LLM review or judge, slower, non-deterministic). Best sensors emit messages "optimised for LLM consumption", for example linter messages that carry the fix ("a positive kind of prompt injection").
- Place checks by cost and speed ("keep quality left"); run continuous drift and health sensors outside the change lifecycle; sampled AI judges on runtime responses.
- Three regulation categories: maintainability (well served by tooling), architecture fitness, behaviour (weakest: AI-written tests are not enough; approved-fixtures pattern helps in some areas).
- Open questions she lists: keeping guides and sensors coherent, "if sensors never fire, is that high quality or inadequate detection?", and a missing way to measure harness coverage like mutation testing does for tests.
- Ashby's law: narrowing topology (templates) makes a comprehensive harness feasible.
- She notes the OpenAI post lacks concrete examples (SNIPPET from search; I did not open the memo).

## 2. Taxonomy of harness components
Synthesized from LangChain's anatomy post, Böckeler, OpenAI, Anthropic Managed Agents (each OPENED).
1. **Instructions and knowledge:** system prompts, AGENTS.md as index, versioned in-repo docs, skills, rubrics, few-shot calibration examples.
2. **Tools and interfaces:** tool definitions and descriptions, MCP, code execution or bash, response shaping, credential vaults.
3. **State and memory:** filesystem, git, progress files, append-only session log, notes, dreaming or consolidation passes.
4. **Context management:** compaction, tool-result clearing, just-in-time retrieval, resets with handoff, sub-agent isolation.
5. **Orchestration:** planner, generators, evaluators, sub-agent spawning, routing across models and effort levels, sprint contracts, locks.
6. **Computational controls:** linters, structural tests, schema validation, type checks, oracles, checklists, loop detectors, budget and time warnings (middleware or hooks).
7. **Inferential controls:** LLM evaluators and judges, calibrated and run in isolation per dimension.
8. **Runtime and safety:** sandbox, permission and credential boundaries, injection defenses, rainbow deploys, resume from log.
9. **Observability:** full traces, transcripts, cost and token metrics, trace-derived datasets.
10. **Evals and the improvement loop:** capability and regression suites, graders, noise measurement, outer-loop optimizers (trace analyzer, GEPA, ACE, Meta-Harness, AHE).
11. **Entropy control:** doc-gardening, golden-principle scans, quality grades, drift sensors.

## 3. Practices ranked by evidence strength
**A. Measured results (controlled or ablated, with numbers)**
1. Separate evaluator, tuned skeptical, with thresholds and a pre-agreed "done" contract: solo versus harness comparison, one author's runs, n small (Anthropic harness-design). Strongest on tasks at the edge of model ability; it became unnecessary overhead on easier tasks after a model upgrade.
2. Self-verification gates and loop detectors in the harness: 52.8% to 66.5% with model fixed (LangChain). Single benchmark, partly disclosed overfitting risk.
3. Trace-driven harness optimization: Meta-Harness (+7.7 points, 4x fewer tokens), AHE (69.7% to 77.0%, transfers), GEPA, ACE. Peer-style preprints, benchmark settings, not production pipelines. Gains came from giving the proposer raw traces and code, not summaries.
4. Evaluation infrastructure noise: 6-point swing from resource limits alone; leaderboard gaps under 3 points are suspect (Anthropic). Directly relevant to any keep/revert rule with a noise floor.
5. Harness effect on accuracy is small and on cost is large, when model is held fixed: 2610.04433 (heaviest versus lightest harness equivalent within 5 points on 447 tasks; swapping harness flips 13% of tasks, the same as rerunning; cost per task up to 3x), 2609.11987 (no resolvable average advantage, wide CIs), 2611.12122 (cost differences up to 2.6x; 35% savings without accuracy loss in proof-of-concept). Counterweight: 2605.23950 argues harness variance can dominate in long-horizon settings. Conclusion: measure rerun variance before crediting a harness change.
6. Token reduction is not cost reduction: 38.4% fewer tool-output tokens raised billed cost 6.8% because of cache effects (2607.12161). Measure billed cost, not tokens.
7. Citation and claim verification: citation links resolve more than 94% of the time but fact-check accuracy of cited claims is only 39-77%, and drops about 42% as tool calls scale from 2 to 150 (2605.06635); 84.7% of final-report errors in one multi-agent system originate at the orchestrator, and two simple interventions raised citation recall by 5% (2608.24306); "claim smoothing" makes reports sound more decisive than sources support across 7 systems (2610.35793).
8. Centralized verification limits error propagation in multi-agent systems (2512.08296), and effort scaling by query difficulty (Anthropic research system, first-party measured 90.2% gain from the multi-agent design).
9. Judge bias is real: self-preference bias across 20 LLMs, reduced 31.5% by multi-dimensional rubric decomposition (2604.22891); agreement between judges or samples is only a weak, regime-dependent proxy for correctness (rho 0.20-0.59) and worst for the most consistent frontier model (2607.08065).
10. Reasoning-effort allocation: "sandwich" of high effort on planning and verification beat uniform xhigh (63.6% vs 53.9%, LangChain). Anthropic's postmortem shows a default effort change silently lowered quality.

**B. First-party production reports (no controls)**
- OpenAI agent-first repo: map-style AGENTS.md, custom lints with remediation messages, doc-gardening, golden-principle GC, per-worktree observability, agent-to-agent review.
- Anthropic: JSON feature list with pass flags, progress files, resets versus compaction, rainbow deploys, resume from log, vaulted credentials, deterministic sampling in test harnesses, GCC-style known-good oracle, artifact handoff between subagents.
- Anthropic postmortem: broad ablation evals for prompt changes, staged rollout.
- Böckeler's regulation model and Thoughtworks anecdotes (janitor armies) are experience reports.

**C. Opinion or framing**
- Hashimoto's "never repeat a mistake" rule; the Fowler harness-template idea; Ashby's-law argument; Natural-language harness documents as a representation (the paper shows parity, not superiority).

## 4. Emerging or novel approaches, with what the evidence actually shows
- **Evaluator/verifier separation and calibration.** Anthropic (measured by one author): tune a standalone evaluator by reading its logs and correcting divergences; few-shot score breakdowns; hard thresholds; contract before work. LangChain (snippet): inspect the verifier's own reasoning to catch weak verifiers and reward hacking. OpenAI cookbook agent-improvement loop (OPENED, notebook): LLM-generated Promptfoo evals as a gate before a coding agent applies harness changes, with human approval of the diff as the default.
- **Deterministic checks that replace or gate model judgments.** Böckeler (computational first, inferential selectively); Anthropic evals (code graders where possible, LLM where needed); OpenAI (invariants as lints; parse at the boundary); C compiler (oracle). No source measures the gain from replacing a judge with a check, so this stays a design principle with strong convergent first-party support, not a measured effect.
- **Known-answer probes, canaries, planted controls.** I found no primary source describing planted controls for online quality measurement of agent pipelines. SNIPPET-only: practitioner posts on "golden prompt" health checks (agentstatus.dev, klu.ai) and a sleeper-agent paper using known-answer questions (arXiv 2511.15992); these are vendor or niche, and one claim says deterministic-looking probes can vary more than expected, so per-probe variance should be measured. Adjacent first-party evidence: Anthropic's eval-awareness post shows that benchmark-style items can be recognized and gamed by a capable agent, and the quality postmortem shows internal evals missing a regression, both arguments for randomized and rotating probes rather than fixed ones. Treat this whole item as unverified.
- **Quote and citation verification against sources.** Strong research basis (section 3, item 7): fetch the cited source and check the claim against it, per citation-claim pair; check at each agent hop, since errors are introduced at the orchestrator and travel verbatim. Snippet-based checkers are high precision and low recall, and default to "unsupported" when retrieval fails (DeepFact 2603.05912, SNIPPET).
- **Cross-model disagreement as a signal.** 2603.25450 (OPENED abstract): a second model's surprise at the first model's answer tokens (Cross-Model Perplexity and Entropy) beats within-model uncertainty on MMLU, TriviaQA and GSM8K. It needs token log-probabilities and a forward pass, so it does not apply through headless coding-agent CLIs. Caution from 2607.08065: agreement can come from shared bias, and different model families are not a guarantee of independence. Neither measures disagreement between full agent outputs on research claims.
- **Harness self-improvement from traces.** Section 3 A.3. Practical recipe differences: Meta-Harness gives the proposer the whole history through a filesystem; AHE requires each edit to declare a prediction checked next round and keeps component edits file-level and revertible; ACE uses delta updates to avoid collapsing a playbook; LangChain warns trace-driven fixes can overfit single tasks. The user's fixed train/test split and keep/revert rule match the strongest of these designs.
- **Harness simplification as models improve.** Anthropic (OPENED, three posts): remove one component at a time, re-test on each new model, and expect evaluator value to depend on task difficulty. LangChain agrees guardrails "will almost surely dissolve over time".
- **Cost and effort routing.** LangChain reasoning sandwich; Anthropic prompt-embedded effort scaling and the effort-default postmortem; 2610.04433 and 2611.12122 show cost is set by the preamble (system prompt plus tool schemas sent on every call) times steps, so trimming tool schemas and step counts is the main lever. No source measures routing a small model to easy rubric questions.
- **Loop detection.** One measured source: LangChain LoopDetectionMiddleware, part of a package that moved the score; its isolated effect was not reported separately.
- **Context management across long runs.** Anthropic: resets plus handoff for models with context anxiety, compaction otherwise; reset need disappeared on Opus 4.5. Managed Agents: keep the full log outside the window so compaction is reversible.
- **Architecture rules enforced by tests with remediation messages; garbage collection of drift.** OpenAI (first-party, no controls) and Böckeler (framing, drift sensors). The Anthropic memory post adds a parallel for notes: periodic verification of stored notes against transcripts, because wrong notes propagate.
- **Eval and benchmark hygiene.** Resource and infrastructure configuration is a first-class variable (Anthropic); disclose harness configuration (2605.23950); rerun the same configuration to calibrate noise (2610.04433).

## 5. Anti-patterns the sources warn about
- One giant instruction file (OpenAI): crowds context, rots, unverifiable.
- Letting the generator grade itself (Anthropic): confident praise of mediocre work; an untuned evaluator also rationalizes away real bugs.
- Rigid step-sequence grading (Anthropic evals): punishes valid paths. Grade outcomes.
- One-sided eval sets (Anthropic): optimize toward always searching or never searching.
- Adding hundreds of evals without curation (LangChain): illusion of improvement; every eval shapes behavior.
- Overfitting harness fixes to specific traces (LangChain); proposer given compressed feedback (Meta-Harness).
- Using agent count as a quality lever without a verification point (Google scaling paper; Anthropic 15x token cost).
- Trusting agreement between judges or samples as correctness (2607.08065).
- Comparing agents or harnesses without disclosing configuration, resources and reruns (Anthropic noise post, 2605.23950, 2610.04433).
- Narrow eval confidence before a prompt or default change ships (Anthropic postmortem).
- Giving the agent credentials in the same container as untrusted content (Managed Agents).
- Irreversible context pruning with no stored log (Managed Agents).
- Reading token counts as cost (2607.12161).
- Counting a citation as verified because the URL resolves (2605.06635).
- Leaving stale harness scaffolding after a model upgrade (Anthropic, LangChain).
- Always-on loops with no budget (C compiler: infinite loop; one instance killed itself with `pkill -9 bash`).
